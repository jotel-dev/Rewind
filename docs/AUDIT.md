### Known design limitation

The seller's `markFulfilled` does not require a contract-level post-quantum signature. A compromised seller key could mark a funded order fulfilled early if the chain admits that account's EVM transaction, for example under an open window that permits calls to Rewind. Fulfilment has no timeout, and refund requires `State.Funded`, so the early state change can block the buyer's timeout refund. The stored buyer must still submit a valid ML-DSA-87 release authorisation to move the funds through Rewind. This limitation is accepted for the MVP. See [Rewind.sol:77–104](../contracts/contracts/Rewind.sol#L77-L104) and “rejects refund after fulfilled” ([Rewind.ts:415](../contracts/test/Rewind.ts#L415)).
